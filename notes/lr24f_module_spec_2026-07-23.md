## 하드웨어
- 2.4GHz ISM 대역, LoRa 변조 + FHSS(주파수 호핑)
- 8g, 최대 27dBm(500mW) 송신출력, 공식 10km+ 도달거리(구매처 표기)
- 투명 전송(transparent) — MAVLink 포함 모든 프로토콜/데이터 호환
- CP2102 USB-UART IC, QGroundControl(Android) 호환
- Pixhawk/ArduPilot/PX4 대상. **2.4G 수신기와 대역 겹침 주의** — 915MHz(ELRS 915 등)
  수신기 조합 권장 (이 프로젝트는 별도 FC 링크 921600 PL011 유선이라 무관할 가능성,
  단 영상링크(WFB-ng 5.8GHz)와의 대역 분리는 기존 lora_protocol_v2_spec.md에 이미 명시됨)

## 데이터 전송 (air rate, 모듈 설정 — AT 명령/설정도구로 변경 가능, 부품 교체 불요)
| 옵션 | 값 |
|---|---|
| 전송 속도(air rate) | **2.4K Byte/s(기본값)** / 4K / 8K / 20K Byte/s |
| 최대 단일 패킷 길이 | 20K Byte |
| UART 보레이트(JST-GH) | 9600/19200/38400/**57600(기본)**/115200/230400/460800/500000/921600 |
| UART 보레이트(USB) | **57600(기본)**/115200/921600 |

## 이번 대화에서 확인된 것
1. **air rate 상향 가능 — 부품 교체 불요**, 모듈 설정만으로 최대 8.3배(2.4K→20K Byte/s).
   단, SF/BW 상향형 무선 설정의 일반 트레이드오프(도달거리·간섭내성 저하)는 물리적으로
   여전히 적용 — 실외 실측 전까지 상향 폭 신중히 판단 필요
2. **기존 "air rate 표기 오류 의심"(어제 밤 추가 검토 항목) 근거 소멸**: "2.4KB/s(2400
   bytes/s)"는 매뉴얼의 "2.4K Byte/s"와 정확히 일치 — 단위 혼동이 아니라 **원래 표기가
   맞았음**. UART 57600bps(비트 단위)는 애초에 별개 수치라 정상.
3. **UART는 921600까지 지원** — 현재 57600 사용 중이나 air rate를 올릴 경우를 대비해
   UART도 함께 올릴 여지 있음(단 이번 대화에서 코드 변경은 하지 않음, 실제 설정 변경은
   물리적 모듈 접근+설정도구 필요)
