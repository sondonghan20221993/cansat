# 5m_1 실제 드론 데이터 개선 시도 (2026-07-27 계획)

시뮬레이션(`real_test_4m_old`) 트랙에서 검증된 개선 방식들을 **실제 드론 데이터(5m_1)** 에 하나씩 단일 변수로 적용해보는 트랙. GT가 없어 CD/notch 같은 정량 지표는 못 쓰고, 기존 베이스라인과의 **육안 비교**로만 판단한다.

## 베이스라인 (2026-06-29/30 기존 완료, 재실행 없음)

| 항목 | 값 |
|---|---|
| 원본 이미지 | `drone_real/5m_1/frame_*.jpg`, 55장, 1920×1080 |
| SfM | MASt3R-SfM, `scene_graph=swin-5`(기본값), 카메라 1개 공유(shared intrinsics), focal 1343.54px |
| Prior | native MASt3R 점군, 필터링 없음 |
| 학습 | GS-2M, `--iterations 30000`, 추가 플래그 없음 (opacity_reduce 등 없음), 결과: `drone_real_5m_1__gs2m` |
| 메시 | `render.py --extract_mesh --skip_test` → `tsdf_post.ply` (152MB, 3.0M V) |
| 평가 | GT 없음 → 시각 비교만 |

## 실험 원칙

- **한 번에 하나만 바꾼다** — 베이스라인 대비 정확히 한 가지 요소만 교체해서 그 요소의 효과를 육안으로 판단
- res1024는 제외(실패作 아니라 아직 아예 안 돌려본 것이라 이번 라운드에선 보류)
- 학습 이미지는 항상 원본(전처리는 SfM/prior 추정에만 관여) — 시뮬레이션 트랙과 동일 원칙

### GT-pose 없이 박스(파란색) 기반 스케일 추정 (2026-07-27)

카메라 GT pose가 없어 시뮬레이션처럼 Umeyama 정렬은 불가. 대신 메시의 파란색 점(물리적으로 GT와 동일한 박스+ㄷ자 구조물)을 색상 기반으로 클러스터링해 bbox를 재고, GT 실측(ㄷ자 전체 조합 130×105.5×36cm, 단일 큐브 55×40×36cm, 서버 `gt_mesh/gt_cubes.ply` 및 `Cube8.ply` 실측)과 비교. 스케일(1)만 구할 수 있고 회전·이동(6자유도)은 여전히 미해결 — 전체 CD는 계산 불가, 박스 형태/스케일 비교까지만 가능.

| 실험 | 파란점 수 | bbox(재구성단위, 정렬) | vs ㄷ자전체 배율(장/중/높이) |
|---|---|---|---|
| baseline | 33,856 | 0.575 / 0.529 / 0.252 | 225.9 / 199.4 / 143.0 |
| exp0(retinex+clahe) | 35,354 | 0.568 / 0.553 / 0.320 | 228.9 / 190.8 / 112.4 |
| exp3(native+SOR) | 33,932 | 0.576 / 0.529 / 0.251 | 225.9 / 199.3 / 143.3 |
| exp4(retrieval-20-5) | 34,995 | 0.587 / 0.578 / 0.354 | 221.3 / 182.5 / 101.7 |
| exp8(voxel k1.4) | 33,938 | 0.576 / 0.529 / 0.252 | 225.9 / 199.4 / 142.7 |

- baseline/exp3/exp8은 같은 SfM(native swin-5) 위에서 필터만 다르게 한 것이라 스케일·형태 거의 동일 — 예상대로, 검증 완료
- exp0/exp4는 독자 SfM이라 스케일 자체가 다름(당연). 장·중축 배율 일치도는 baseline 계열(12.5% 차이)이 exp0/exp4(18~19% 차이)보다 좋음
- 모든 실험에서 높이축만 유독 배율이 낮음(101~143) — 드론 궤도상 수직 삼각측량이 약해서일 가능성이 있으나 확정 아님, 수치만 기록

### 박스 스케일로 전체 씬 크기 역산 (2026-07-27)

박스 배율(장·중축 평균, 높이축 제외)을 전체 메시 bbox에 적용해 실제 크기(m) 추정.

| 실험 | scale(cm/unit) | 씬 bbox(추정, 정렬) |
|---|---|---|
| baseline | 212.7 | 3.9m / 14.1m / 14.2m |
| exp3(SOR) | 212.6 | 3.9m / 13.7m / 14.0m |
| exp8(k1.4) | 212.7 | 3.9m / 13.7m / 13.9m |
| exp0(retinex+clahe) | 209.9 | 6.1m / 13.4m / 13.6m |
| exp4(retrieval-20-5) | 201.9 | 5.9m / 13.5m / 15.2m |

- baseline/exp3/exp8(동일 SfM, 포즈 공유): 수평 두 축(13.7~14.2m) 및 높이축(3.9m) 전부 사실상 동일 — 스케일 역산 방법 자체의 일관성 검증됨
- exp0/exp4(독자 SfM 실행): 수평 두 축은 baseline과 비슷(13.4~15.2m)한데, **"높이"축만 3.9m → 5.9~6.1m로 50%+ 크게 벌어짐** — 표본 2개뿐이라 단정은 어려우나, 새로 SfM을 돌릴 때마다 수직 방향 재구성이 유독 불안정할 가능성을 시사
- exp4는 전체 스케일 자체는 다른 실험과 같은 자릿수라 기하가 완전히 틀어진 건 아님 — PSNR 22.11 저하는 기하보다 photometric 쪽 문제일 가능성에 무게가 실림(단정 아님)
